# Changelog — RTS-MK1

All notable changes to **RTS-MK1** (`https://rts-mk1.orbital8.cloud`) follow strict non-reusable `v1.x.y` versioning.

## [v1.11.1] — 2026-10-29

### Fixed & Changed
- **Root-Cause Fix for French Diacritic & Accented Glyph Rendering (`src/app/layout.tsx`, `tailwind.config.ts`, `src/components/ui/primitives.tsx`, `src/components/lobby/portal-command-center.tsx`, `src/components/hud/classic-sidebar-hud.tsx`, `src/app/game/[lobbyId]/page.tsx`, `src/store/game-store.ts`, `src/renderer/minimap-renderer.ts`)**:
  - **Self-Hosted `Inter` & `JetBrains Mono` Webfonts with Full `latin` + `latin-ext` Subsets**:
    - Bundled `Inter` (`--font-sans`) and `JetBrains_Mono` (`--font-mono`) via `next/font/google` in `src/app/layout.tsx` with `subsets: ["latin", "latin-ext"]` so Next.js self-hosts `.woff2` files containing native French accented glyphs (`é, è, ê, ë, à, â, ù, û, ô, î, ï, ç, œ`) with uniform x-height and stroke metrics.
    - Eliminated `ui-monospace` and generic `monospace` from `tailwind.config.ts` and switched root UI containers (`layout.tsx`, `portal-command-center.tsx`, `classic-sidebar-hud.tsx`, `page.tsx`, `primitives.tsx`) from `font-mono` to `font-sans` (with `tabular-nums` for numeric counters), preventing browsers from resolving `ui-monospace` to local small-caps/ASCII-only system fonts where accented letters fell back to tall capital-sized glyphs.
  - **Natural-Case French Accents Without Forced Capital Diacritics**:
    - Removed forced `uppercase` (`text-transform: uppercase`) from `Button` and `Badge` (`src/components/ui/primitives.tsx`), portal headings/buttons (`src/components/lobby/portal-command-center.tsx`), HUD headers (`src/components/hud/classic-sidebar-hud.tsx`), radar canvas offline text (`src/renderer/minimap-renderer.ts`), and EVA status banners (`src/store/game-store.ts`, `src/app/game/[lobbyId]/page.tsx`), ensuring accented characters render naturally as lowercase (`é`, `è`, `ê`, `à`) rather than forced capital accented letters.
- **Coherent Victory vs. Game Over (Defeat) End-of-Match Screen (`src/app/game/[lobbyId]/page.tsx`, `src/store/game-store.ts`)**:
  - Replaced the single generic end-of-match card (which previously displayed a golden `Trophy` cup even after losing a match) with two distinct, context-coherent tactical screens inside `data-testid="match-end-overlay"`:
    - **Victory (`winnerPlayerId === playerId`, `data-testid="match-victory-card"`)**: Displays the golden `Trophy` medallion (`data-testid="victory-trophy-icon"`), *"Opération victorieuse • Secteur pacifié"* badge, *"Victoire Totale !"* title, victorious clan & map seed summary, and *"Retourner à la sélection du clan"* CTA.
    - **Game Over / Defeat (`winnerPlayerId !== playerId`, `data-testid="match-gameover-card"`)**: Displays a crimson `Skull` medallion (`data-testid="gameover-skull-icon"`, zero trophy cup), *"Signal EVA interrompu • Base anéantie"* alert badge with `ShieldAlert`, *"GAME OVER — Défaite Tactique"* title, defeat narrative explaining the destruction of the command base, tactical summary (*"Base détruite (Échec)"* + victorious enemy commander), and a crimson `variant="danger"` *"Retourner à la sélection du clan"* button.

## [v1.10.0] — 2026-10-28

### Added & Changed
- **Procedural Map Generation by Seed & Dedicated Placement Rules Section (`src/shared/map-generator.ts`, `src/shared/constants/index.ts`, `src/shared/types/index.ts`, `src/engine/simulation.ts`)**:
  - Created a deterministic procedural battlefield generator (`generateProceduralMap`, Mulberry32 PRNG `createSeededRng`, 2D value & FBM noise `seededValueNoise2D` / `seededFbm2D`, `normalizeMapSeed`, `generateRandomMapSeed`) driven by a 32-bit `mapSeed` so any match can be generated randomly or reproduced identically from its seed.
  - Added a dedicated, structured section (`MAP_GENERATION_RULES` & `validateGeneratedMapAgainstRules`) centralizing all placement and safety constraints so they can be studied and refined in future iterations:
    - **Enemy Base Separation (`spawnRules`)**: Enemy bases are never generated closer than `minEnemyBaseDistanceTiles: 96` blocks (`~118–136` blocks on `160×160`), with `minBorderMarginTiles: 8`, `maxSpawnAnchorJitterTiles: 10`, an `8×8` `CONCRETE_SLAB` pad surrounded by `STONE` (`9.2` blocks) and `DIRT` (`13.5` blocks) halos, and a `15`-block obstacle-free safety perimeter.
    - **Ore Vein Placement (`oreRules`)**: Ore tiles (`TERRAIN_KIND.ORE`) are strictly forbidden within `minDistanceFromSpawnTiles: 20` blocks of any spawn center while guaranteeing a natural expansion vein within `maxNaturalOreDistanceFromSpawnTiles: 34` blocks of each base, plus regional expansion veins and `5` high-yield contested central/flank basins (`minDistanceBetweenOrePatchesTiles: 16`).
    - **Silver Mine Boulders (`silverMineRules`)**: `2×2` Silver Ore boulders (`TERRAIN_KIND.SILVER_ORE`) are forbidden within `minDistanceFromSpawnTiles: 28` blocks of any spawn center, with `1` regional deposit per quadrant (`<= 52` blocks from spawn) and `2` contested central deposits separated by at least `minDistanceBetweenSilverDepositsTiles: 24` blocks and `minClearanceFromCliffsTiles: 3` blocks for Constructor Bot docking. Exempted `SILVER_MINE` from `BASE_BUILD_RADIUS_TILES` so players can deploy Silver Mine blueprints directly on distant `2×2` Silver Ore boulders.
    - **Terrain, Cliffs & Destructible Trees (`terrainAndCoverRules`)**: Procedural canyon ridges (`CLIFF`, `>= 28` blocks from spawns, `>= 8`-block tactical pass widths) and `14` multi-species tree groves (`>= 15` blocks from spawns).
- **Enlarged Battlefield Sizes (`>= 4×` Larger, `160×160` Active Default = `4.94×` Area) & Engine Scaling (`src/shared/map-generator.ts`, `src/shared/constants/index.ts`, `src/shared/schemas/commands.ts`, `src/engine/fog/fog-of-war.ts`, `src/engine/pathfinding/astar.ts`, `src/app/game/[lobbyId]/page.tsx`)**:
  - Defined `MAP_SIZE_PRESETS` identifying the optimal sizes above the `4×` threshold (`LEGACY_1X` `72×72` = `5,184` tiles; `SKIRMISH_4X` `144×144` = `20,736` tiles [`4.0×`]; `TACTICAL_5X` `160×160` = `25,600` tiles [`4.94×` — active default]; `STRATEGIC_7X` `192×192` = `36,864` tiles [`7.11×`]; `COLOSSAL_9X` `216×216` = `46,656` tiles [`9.0×`]).
  - Updated active `MAP_WIDTH_TILES = 160` and `MAP_HEIGHT_TILES = 160` (`4.94×` larger than `72×72`) and `BASE_BUILD_RADIUS_TILES = 24`.
  - Scaled coordinate bounds in `src/shared/schemas/commands.ts` (`.max(511)`), fixed 11-bit sight-signature coordinate packing in `FogOfWarManager` (`src/engine/fog/fog-of-war.ts`), increased `AStarPathfinder` default `maxIterations` to `4096` (`src/engine/pathfinding/astar.ts`), and auto-centered the tactical camera on the player's Construction Yard on snapshot load (`src/app/game/[lobbyId]/page.tsx`).
- **Per-Match Seed Logging (`src/engine/simulation.ts`, `src/server/lobby-manager.ts`, `src/server/db/index.ts`, `src/shared/schemas/deltas.ts`, `src/shared/schemas/lobby.ts`, `src/store/game-store.ts`, `src/components/hud/classic-sidebar-hud.tsx`)**:
  - Every match now generates or normalizes a `mapSeed` and records it at launch in:
    1. Server stdout logs (`[RTS-MK1][MAP_SEED] Simulation initialisée` & `Partie démarrée | lobbyId=... | seed=... | taille=160x160`).
    2. Persistent SQLite table `match_seed_logs` (`recordMatchSeedLog`, `listRecentMatchSeedLogs`).
    3. In-memory simulation audit buffer (`RtsSimulation.getSeedLogs()`).
    4. `EVA CENTRAL` lobby chat log, `FullSnapshot.mapSeed`, and the tactical HUD radar header (`SEED #<mapSeed>`).

- **Agent 01 (`src/shared/`)**: Strict Zod validation schemas (`commands`, `deltas`, `lobby`, `profile`, `env`), inferred TypeScript types (`strict: true`, zero `any`), and full Command & Conquer / Dune 2000 unit, structure, tech-tree, and faction balance constants (`GDI`, `NOD`, `ORDOS`).
- **Agent 02 (`src/engine/`)**: Deterministic 20 Hz ECS simulation engine (`simulation.ts`), binary-heap A* pathfinding with deterministic spatial tile reservation (`pathfinding/`), two-layer Shroud & Fog of War (`fog/`), Harvester-Refinery-Silo economy loop, power deficit penalties, 4 parallel production queues (`BUILDING`, `DEFENSE`, `INFANTRY`, `VEHICLE`), skirmish AI controller, and compact Zod-validated Delta + Snapshot generation.
- **Agent 03 (`src/server/`, `src/app/api/`)**: Single Active Match Mutex (`lobby-manager.ts`) enforcing at most 1 active (`STARTING` / `IN_PROGRESS`) match with ordered FIFO `QUEUED` lobby rank broadcasting and a 10s/60s `ping/pong` Watchdog automatic lock release; authoritative WebSocket server (`ws-server.ts`) on `/ws`; persistent SQLite WAL commander profile & match history database (`src/server/db/`).
- **Agent 04 (`src/app/`, `src/components/`, `src/store/`)**: Portal, live server mutex badge & lobby browser, waiting/queue room, Classic Westwood C&C / Dune 2000 sidebar HUD (`src/components/hud/`) with radar canvas slot, discretized Tailwind power & progress bars, 100% Tailwind CSS with zero inline `style` attributes, and Zustand store bridge (`src/store/game-store.ts`).
- **Agent 05 (`src/renderer/`)**: Asynchronous batched `OffscreenCanvas` -> `ImageBitmap` procedural vector/bitmap sprite atlas generator (`generator/atlas-generator.ts`) across 16 rotation angles and faction team color masks with explicit GPU `.close()` cleanup; orthogonal camera (`camera.ts`); 60+ FPS linear-interpolated tactical world canvas renderer (`world-renderer.ts`); real-time radar minimap renderer (`minimap-renderer.ts`).
- **Agent 06 (`src/audio/`)**: Procedural Web Audio API sound synthesizer (`synthesizer.ts`), 4-bus mixer (`mixer.ts`) with strict 4-instance / 80ms polyphony limiter and automatic EVA ducking, and camera-relative stereo panning & distance attenuation (`spatial.ts`).
- **Agent 07 (`Dockerfile.web`, `Dockerfile.ws`, `docker-compose.yml`, `infra/`)**: Multi-container Docker Compose infrastructure (`reverse-proxy`, `web`, `ws-server`, `db`) tagged `v1.0.0`, non-root user execution, CPU/RAM limits, Zod environment validation, and HTTPS + `/ws` deployment on `https://rts-mk1.orbital8.cloud`.
